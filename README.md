# Предсказание индекса селективности (SI) малых молекул против вируса осповакцины (VACV)

Решение хакатона «Molecular activity prediction»: по SMILES-записи молекулы (и текстовым полям `Title`, `strain`,
`Culture`) предсказать `SI VACV = CC50 / IC50`. Метрика соревнования — **MSE по «сырому» SI**.

| этап | OOF-MSE (повторный 5-fold × 6) |
|---|---|
| предсказывать среднее | 22.08 M |
| первая модель (химия + источник данных, ExtraTrees + признаки-соседи) | 8.7 M |
| + признаки происхождения SMILES (см. «Анатомия данных», п. 5) | 6.26 M |
| **итог: ансамбль 32 моделей + обучение на 100% данных + внешний набор** | **≈ 5.97 M** (RMSE ≈ 2 440) |
| нижняя граница при идеальном классификаторе «потолка» | ≈ 4.08 M |

Нижняя граница почти целиком состоит из одной записи (SI = 36 066, см. ниже): её невозможно предсказать ни одной моделью.

* Запрещённые организаторами колонки `CC50_uM` и `IC50_uM_VACV` **не используются нигде** (удаляются при чтении, проверка в тестах).
* Внешний набор данных (ChEMBL, 2 452 записи, DOI у 100%) собирается скриптом из репозитория и участвует в обучении.
* Весь конвейер воспроизводится одной командой: `make all` (≈ 10–12 минут на Apple M4) → `submissions/submission.csv`.

## Быстрый старт

```bash
pip install -r requirements.txt && pip install -e . --no-deps
# положить train.csv, test.csv, sample_submit.csv в data/raw/
make all            # = python -m vacv_si run-all -c configs/exp/final.yaml   (≈ 10–12 минут на Apple M4)
make test           # инварианты: нет запрещённых колонок, нет утечки в фолдах, свойства ядер, сборка внешних данных
```

> macOS: для LightGBM/XGBoost нужна библиотека OpenMP: `conda install llvm-openmp` (или `brew install libomp`).
> Без неё эти две модели автоматически пропускаются, остальное работает.

Отдельные шаги: `make prepare`, `make external` (скачать ChEMBL и собрать датасет), `make cv`, `make ensemble`, `make report`.
Версии библиотек, с которыми получены результаты, — `requirements-lock.txt`. Все генераторы случайных чисел фиксированы,
повторный запуск даёт те же числа.

## Анатомия данных (что мы узнали и на чём построено решение)

1. **Таргет — смесь.** `SI == 10000` ровно (25% train) — это не «очень селективно», а метка «IC50 в источнике отсутствует»
   (81 из 81 строк с пустым IC50 имеют SI = 10000). Остальные значения — тяжёлый хвост (медиана ≈ 6, максимум 36 066).
   Из-за MSE по сырому SI ≈ 81% дисперсии таргета — это бернуллиевская часть «потолок / не потолок».
   Поэтому модель **двухчастная**, а предсказание — условное среднее (оптимальное для MSE):

   `SI_hat(x) = p(x) · 10000 + (1 − p(x)) · M(x)`

   где `p(x)` — откалиброванная вероятность «потолка» (задача `clf`), `M(x)` — ожидаемый SI не-потолочной записи,
   восстановленный из регрессии `log10(SI)` (задача `reg`) поправкой Duan (smearing); способ (константа / smearing / изотоническая / степенная / групповой smearing)
   выбирается вложенной CV. Групповая поправка на тяжёлые серии проверена и оказалась хуже глобальной.
2. **Источник решает.** Таблица — мозаика из статей и скринингов. Точные *сырые* строки `strain`/`Culture`/`Title`
   (включая лишние пробелы и запятые!) идентифицируют партию данных, а «потолок» — свойство партии:
   `HELA cells` — 11 из 11 «потолков», `MT-4` — 8 из 8, `ectromelia (strain K-1)` с двойным пробелом — 5 из 5.
   Поэтому категориальные признаки строятся из сырых строк, а не из «очищенных».
3. **Сплит случайный.** Сходство тестовых молекул с train (медианный максимум Танимото 0.71) совпадает с train→train
   leave-one-out (0.68) — значит, честная валидация = обычный повторный стратифицированный K-fold, без scaffold-сплитов.
4. **Выбросы.** Одна запись (SI = 36 066) даёт 94% суммы квадратов не-потолочных значений. Этого не победить: поэтому
   итоговый MSE определяется выбросами теста и качеством классификатора «потолка».
5. **Происхождение SMILES (признаки `@style`).** Записи, пришедшие из ChEMBL/PubChem, содержат канонический SMILES RDKit,
   вручную добавленные — стиль ChemDraw/Marvin. Внутри одного источника это разделяет «есть IC50» и «нет IC50»: в группе
   `Copenhagen / Vero` у канонических строк 0 из 10 «потолков», у остальных 11 из 28. Признаки строятся *только из входной
   колонки SMILES* (канонический ли SMILES, стиль первых символов, нотация колец и стереохимии …). Это артефакт сборки
   датасета, а не химия, поэтому группа вынесена в конфиг и **отключается одной строкой** (`features.groups.style: []`,
   см. `configs/exp/ablate_style.yaml`). Без неё Brier классификатора вдвое хуже (таблица ниже).

## Решение

```
data/raw ──► prepare ──► FeatureStore ──► models (clf, reg) ──► repeated CV ──► blend ──► submission.csv
 train/test   RDKit      блоки признаков   ExtraTrees/CatBoost/   OOF + test      p, M(x)
              стандарт.  + ядра Танимото   LightGBM/XGB/kernel    (+ refit 100%)  SI = p·1e4+(1-p)·M
                            ▲
data/external (ChEMBL) ─────┘  (пул соседей / доп. обучающие строки; строгая политика целостности)
```

* **Предобработка** (`chem/standardize.py`): родительская молекула (без солей), нейтрализация, канонический SMILES, InChIKey.
  Сырые строки сохраняются для признаков источника.
* **Признаки** (`features/`): счётчики фингерпринтов (Morgan 1/2/3, AtomPair, TopologicalTorsion, RDKit-paths, Avalon, MACCS,
  ErG, MQN), 203 RDKit-дескриптора, признаки источника (`meta`: сырые и нормализованные `strain`/`Culture`/`Title`, партия
  PubChem SID, размеры партий), признаки происхождения SMILES (`style`), а также **признаки-соседи**: взвешенные по
  сходству Танимото метки ближайших обучающих молекул — в целом и внутри одной партии (leave-one-out, поэтому на обучающих и
  тестовых строках они согласованы).
* **Модели** (`models/`, реестр): ExtraTrees на разных представлениях молекулы (самое сильное семейство), CatBoost с
  нативными категориальными признаками источника, HistGradientBoosting / LightGBM / XGBoost, ядерные модели (KRR, SVM) на
  ядрах Танимото. Для каждой модели — две задачи: `clf` (вероятность «потолка») и `reg` (`log10 SI`).
* **Валидация** (`cv/`): повторный стратифицированный 5-fold × 6 повторов (стратификация по «потолок × источник»);
  для каждой модели сохраняются OOF-предсказания и предсказания всех фолд-моделей на тесте, плюс 6 переобучений на 100%
  обучающих строк (по кривой обучения у CatBoost и ядерных моделей Brier на 8–9% лучше при 95% данных против 80%, у ExtraTrees эффекта нет).
* **Ансамбль** (`ensemble/`): для `clf` — неотрицательный стекинг в logit-пространстве с L2-регуляризацией, минимизирующий
  Brier (он же главный вклад в MSE), для `reg` — среднее лучших моделей; все решения принимаются по вложенной CV на OOF.
  Предсказание теста = среднее фолд-моделей и переобучений на 100%.

Лучшие одиночные модели (метрики — среднее по повторам CV):

| `clf`: вероятность «потолка» | Brier | | `reg`: log10 SI не-потолочных | RMSE |
|---|---|---|---|---|
| ExtraTrees + AtomPair + meta + style | 0.0233 | | CatBoost + внешние строки | 0.6952 |
| ExtraTrees + MACCS/ErG/MQN + дескрипторы | 0.0245 | | CatBoost + признаки-соседи | 0.7061 |
| ExtraTrees + Morgan + дескрипторы | 0.0250 | | CatBoost | 0.7156 |
| CatBoost + внешние строки | 0.0269 | | ExtraTrees (только meta+style) | 0.7224 |
| **блендинг (вложенная CV)** | **0.0209** | | **среднее top-5 (вложенная CV)** | **0.675** |

Полная таблица — `python -m vacv_si report -c configs/exp/final.yaml`, отчёт ансамбля — `reports/ensemble_final.json`.

### Абляции

| компонент | `clf`, Brier: с компонентом / без | `reg`, RMSE log10: с / без |
|---|---|---|
| признаки происхождения SMILES (`@style`) | ExtraTrees 0.025 / 0.053, CatBoost 0.030 / 0.058 (≈ ×2) | CatBoost 0.716 / 0.718, ExtraTrees 0.722 / 0.740 |
| внешние строки как обучающие (CatBoost) | 0.0269 / 0.0302 (−11%) | 0.695 / 0.716 (−2.9%) |
| внешний пул соседей (модели с `knn`) | CatBoost 0.0330 / 0.0335, ExtraTrees ≈ 0 | CatBoost 0.706 / 0.719, XGB 0.726 / 0.735, ExtraTrees 0.751 / 0.748 (чуть хуже) |

В единицах метрики (ансамбль одного и того же состава из 8 `clf` + 7 `reg` моделей): **6.17 M с `@style` против 8.38 M без него**
(`reports/ensemble_subset_final.json`, `reports/ensemble_subset_ablate_style.json`).

Вывод: внешние данные в строгом режиме дают скромный, но устойчивый прирост у CatBoost/XGB; главный источник качества —
правильное представление *источника* данных.

## Внешние данные (требование организаторов)

Подробности — `data/external/README.md`. Кратко:

* **Источник:** ChEMBL REST API (`https://www.ebi.ac.uk/chembl/api/data`), все эндпоинты перечислены в
  `src/vacv_si/external/chembl.py`. Идентификаторы `sid…` в `Title` — это вещества PubChem из ассеев, которые PubChem
  зеркалирует из ChEMBL, поэтому ChEMBL — первичный источник и для них.
* **Результат:** `data/external/vacv_external.csv` — 2 452 записи, 2 010 молекул, 168 статей, **DOI у 100%**; колонки
  `smiles, IC50_uM, CC50_uM, SI, doi` + штамм, клетки, типы значений и т. д.
* **Валидация** (`validate.py`, отчёт `data/external/validation_report.json`): `SI == CC50/IC50`, положительность и
  диапазоны, формат DOI, дубликаты и сверка с train *только по целевой колонке*: у 87% совпавших молекул SI из ChEMBL
  совпадает с точностью до 2% (у 93% — в пределах ×2), то есть наши правила сборки воспроизводят разметку организаторов.
  Запись «активность есть, числа нет» при известном CC50 соответствует «потолку» (13 из 14 таких молекул).
* **Покрытие:** ChEMBL-набор содержит 50% молекул train и 54% молекул test.

### Политика целостности

Раз 54% тестовых молекул есть в ChEMBL, их измеренные значения можно было бы просто «подсмотреть». Мы этого **не делаем**
(`external.drop_overlap_with_eval: true`): записи, молекулы которых совпадают с валидационными/тестовыми (по InChIKey), из
обучения исключаются, а пара «та же молекула» маскируется и в признаках-соседях. Для проверки, чего мы лишаемся, есть
диагностический режим (`configs/exp/ext_ref_ovl.yaml`): он улучшает регрессию `log10 SI` (RMSE 0.74 → 0.60), но **итоговый MSE
не меняется** (OOF 6.55 M против 6.48 M в строгом режиме), потому что вся масса ошибки — это «потолок» и выбросы, которых нет
в ChEMBL (например, записей SI = 36 066 и SI = 2 325 в нашей выгрузке нет). Строгий режим ничего не стоит.

## Как менять решение

Всё управляется конфигом (`configs/base.yaml` + `configs/exp/*.yaml`, наследование через `extends:`, переопределения
`-o a.b.c=значение`); результаты моделей кэшируются по хэшу спецификации, данных и версии кода признаков.

* **Новый блок признаков:** функция `(store, params) -> (матрица, имена)` с декоратором `@register_block("тип")` в
  `features/store.py`, затем строка в `features.blocks` и (по желанию) в группу `features.groups`.
* **Новая модель:** класс с `fit(idx, y, w, ref)` / `predict(idx)` (см. `models/base.py`), регистрация в
  `models/registry.py`, строка в `models.clf` / `models.reg` конфига.
* **Новый эксперимент:** файл `configs/exp/<имя>.yaml` с `extends: final.yaml` и нужными переопределениями; `python -m vacv_si cv -c …`.
* **Новый внешний источник:** модуль в `external/` с таблицей тех же колонок и подключение в `external/collect.py`.
* **Абляции:** `configs/exp/ablate_style.yaml` (без признаков происхождения), `configs/exp/ablate_ext.yaml` (без внешних данных).

```
configs/            base.yaml, exp/{baseline,main,gbm,sweep,final,ablate_*,ext*}.yaml
data/raw/           файлы соревнования (не в git)      data/external/   vacv_external.csv + README + validation_report.json
src/vacv_si/        data/ chem/ features/ models/ cv/ ensemble/ external/ cli.py
tests/              инварианты решения                  reports/         отчёты ансамблей, OOF
submissions/        submission.csv (итог), промежуточные посылки
```

## Ограничения

* 320 обучающих строк и тяжёлый хвост таргета: MSE на любой выборке тестa сильно зависит от единичных выбросов; публичная
  часть лидерборда (≈ 30% теста) — очень шумная оценка.
* Признаки происхождения SMILES используют артефакт сборки датасета (см. выше). Они законны с точки зрения правил
  (используется только входная колонка SMILES), но это не «химия»; решение об их использовании — за командой.
* Один внешний источник (ChEMBL). Отдельный сборщик PubChem не реализован: релевантные ассеи PubChem — зеркала ChEMBL, а
  qHTS-скрининги NCGC не содержат парных CC50/IC50.
* Гиперпараметры подобраны небольшим свипом, а не полным байесовским поиском.
