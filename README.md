# Предсказание индекса селективности (SI) малых молекул против вируса осповакцины (VACV)

Решение хакатона «Molecular activity prediction»: по SMILES молекулы (и входным текстовым полям `Title`, `strain`,
`Culture`) предсказать `SI VACV = CC50 / IC50`. Метрика соревнования — **MSE по «сырому» SI**.

## Итог в цифрах

Все числа **честные (cross-fitted)**: блендинг, поправка на хвост и выбор моделей заново подгоняются внутри каждого
фолда повторной кросс-валидации (5-fold × 6 повторов × 8 разбиений для ансамбля), а не на тех же строках, на которых считается оценка.

| уровень признаков | честный OOF-MSE | MSE без худшей строки | Brier «потолка» | RMSE log10 SI | посылка |
|---|---|---|---|---|---|
| все признаки (основной ответ) | 4.11 M | 0.16 M | 0.0251 | 0.667 | `submissions/submission.csv` |
| химия + условия ассея | 4.21 M | 0.19 M | 0.0723 | 0.722 | `submissions/submission_assay.csv` |
| только химия | 4.16 M | 0.19 M | 0.0797 | 0.740 | `submissions/submission_chem.csv` |
| константа (среднее train) | 4.26 M | 0.23 M | 0.1921 | 1.016 | — |

Числа пересчитаны на **втором релизе данных** (7 ноября организаторы исправили `train_v2.csv`: у неактивных соединений `SI = 0`,
а не 10 000). Строки таблицы экспериментов 1–26 получены на первом релизе (`experiments/README.md`).

* **Метрика держится на нескольких записях**: одна запись (SI = 36 067) даёт 94.5% суммы квадратов таргета, пять записей — 99%.
  Без неё основной ответ даёт **0.16 M против 0.23 M у константы (на 29% лучше)**. Публичный лидерборд (≈ 30% теста) — лотерея:
  достаточно одного выброса в публичной части, чтобы счёт сдвинулся на миллион.
* **Поправка по близнецам** (`ensemble/twins.py`): у 54 из 597 тестовых молекул в train есть близнец (та же связность InChIKey), в том
  числе у записи с SI = 36 067; параметры поправки взяты из пар стереоизомеров внешних данных (корреляция log SI 0.90). Эффект на train
  скромный (4.122 → 4.114 M), потому что близнецов там почти нет; на тесте предсказание для близнеца гиганта меняется с 982 до 7 685.
* **Подсмотр запрещён.** Организаторы сообщили, что использовать записи молекул из `test.csv` во внешних базах нельзя, поэтому
  пайплайн их не смотрит нигде: записи совпадающих с валидацией/тестом молекул (по связности InChIKey) исключаются из обучения и из
  признаков-соседей, это проверяется тестом на всех конфигах. Режим «подмешать запись той же молекулы из ChEMBL» и его конфиги удалены.
* Внешний набор данных (ChEMBL, 2 452 записи, DOI у 100%, каждое число прослеживается до записи ChEMBL) собирается скриптом из репозитория.

### Что сдавать и почему три уровня признаков

Нулевая метка (`SI = 0`: «IC50 в источнике отсутствует», соединение неактивно против VACV) — в основном свойство **источника данных**, а не молекулы.
Поэтому мы сознательно показываем три модели, а не одну:

| уровень | какие входы использует |
|---|---|
| **все признаки** (`configs/exp/final.yaml`) | структура + условия ассея + происхождение данных: шаблон `Title`, номер партии PubChem SID, пробелы и запятые в сырых `strain`/`Culture`, стиль записи SMILES |
| **химия + условия ассея** (`configs/exp/assay.yaml`) | структура + нормализованная клеточная линия + токены вируса/штамма (то, что определяет «что измерено») |
| **только химия** (`configs/exp/chem.yaml`) | только стандартизованная структура молекулы (фингерпринты, дескрипторы, соседи по Танимото, молекулы ChEMBL) |

Задание формулируется как «по SMILES», а для новой молекулы признаков происхождения данных нет — поэтому честный ответ на вопрос
«что умеет модель от структуры» дают два нижних уровня. Верхний уровень использует только колонки, которые организаторы сами
положили в `test.csv` и не запретили, и даёт лучший счёт; два нижних — страховка и честная научная оценка. Организаторы в чате хакатона подтвердили, что `strain` и `Culture` использовать можно; про `Title` и стиль записи SMILES вопрос не задавался. Если организаторы
сочтут признаки происхождения недопустимыми, вторую посылку (`submission_assay.csv` или `submission_chem.csv`) можно сдать вместо основной.

## Быстрый старт

```bash
pip install -r requirements.txt && pip install -e . --no-deps
# положить train_v2.csv, test.csv, sample_submit.csv в data/raw/   (train_v2 — исправленный организаторами набор: у неактивных SI = 0)
python -m vacv_si run-all -c configs/exp/final.yaml          # основной ответ -> submissions/submission.csv  (≈ 12 минут на Apple M4)
python -m vacv_si cv -c configs/exp/assay.yaml && python -m vacv_si ensemble -c configs/exp/assay.yaml   # -> submissions/submission_assay.csv
python -m vacv_si cv -c configs/exp/chem.yaml  && python -m vacv_si ensemble -c configs/exp/chem.yaml    # -> submissions/submission_chem.csv
python -m pytest                                              # 30 тестов на синтетических данных, файлы Kaggle не нужны
python scripts/summarize_results.py                           # таблица уровней выше из reports/ensemble_*.json
```

`Makefile` — необязательная обёртка для macOS/Linux (`make all`); на Windows используйте команды `python -m vacv_si …`.
> macOS: для LightGBM/XGBoost нужна библиотека OpenMP: `conda install llvm-openmp` (или `brew install libomp`); без неё эти
> две модели автоматически пропускаются, остальное работает. Версии библиотек, с которыми получены результаты, — `requirements-lock.txt`.
> Все генераторы случайных чисел фиксированы: повторный запуск с нуля даёт те же числа.

## Анатомия данных (на чём построено решение)

1. **Таргет — смесь.** `SI == 0` ровно (26% train: 81 строка без IC50 и две без CC50) — метка «IC50 в источнике отсутствует»,
   соединение неактивно (в первом релизе данных здесь стояло 10 000 — ошибка организаторов, исправленная в `train_v2.csv`).
   Остальные значения — тяжёлый хвост (медиана ≈ 6, 99-й процентиль ≈ 4 100, максимум 36 067). Поэтому модель **двухчастная**,
   а предсказание — условное среднее (оптимальное для MSE): `SI_hat(x) = (1 − p(x))·M(x)`, где `p` — откалиброванная вероятность
   нуля (задача `clf`), `M` — ожидаемый SI активной записи, восстановленный из регрессии `log10(SI)` (задача `reg`)
   поправкой Duan (smearing) с обрезкой выброса; способ выбирается вложенной CV (групповая поправка на тяжёлые серии проверена и хуже).
   После исправления метрика определяется почти целиком хвостом: одна запись даёт 94.5% суммы квадратов таргета, пять — 99%.
2. **Источник решает.** Таблица — мозаика из статей и скринингов. Точные *сырые* строки `strain`/`Culture`/`Title` (с лишними
   пробелами и запятыми) идентифицируют партию данных, а «потолок» — свойство партии: `HELA cells` — 11 из 11 «потолков»,
   `MT-4` — 8 из 8. Поэтому на верхнем уровне категориальные признаки строятся из сырых строк.
3. **Сплит случайный.** Сходство тестовых молекул с train (медианный максимум Танимото 0.71) совпадает с train→train
   leave-one-out (0.68): честная валидация — обычный повторный стратифицированный K-fold.
4. **Происхождение SMILES.** Записи из ChEMBL/PubChem содержат канонический SMILES RDKit, вручную добавленные — стиль
   ChemDraw/Marvin; внутри одного источника это разделяет «есть IC50» и «нет IC50» (в группе `Copenhagen / Vero` у канонических
   строк 0 из 10 «потолков», у остальных 11 из 28). Признаки строятся только из входной колонки SMILES (канонический ли SMILES,
   Кекуле-запись, нотация колец и стереохимии, доли символов …) и входят в верхний уровень.
5. **Подтверждено организаторами (чат хакатона).** Пустой IC50 означает, что соединение неактивно против VACV; в первом релизе в
   `SI` у таких соединений стояло 10 000, затем организаторы исправили это на 0 (`train_v2.csv`, файл ответов теста обновлён);
   `strain` и `Culture` использовать как признаки можно; внешние данные можно использовать, в том числе считать по ним SI.
   Про `Title` и стиль записи SMILES вопрос не задавался.
6. **Близнецы.** У 54 из 597 тестовых молекул в train есть «близнец» (та же связность InChIKey: дубликат или стереоизомер), среди них
   близнец записи с SI = 36 067. Метка близнеца по внешним данным (пары стереоизомеров одной статьи, корреляция log SI 0.90)
   информативнее, чем её вклад в обычной модели, поэтому ансамбль делает поправку по близнецам (`ensemble/twins.py`, см. ниже).

## Решение

```
data/raw ──► prepare ──► FeatureStore ──► models (clf, reg) ──► repeated CV ──► blend ──► submission.csv
 train/test   RDKit      блоки признаков   ExtraTrees/CatBoost/   OOF + test      p, M(x)
              стандарт.  + ядра Танимото   LightGBM/XGB/kernel    (+ refit 100%)  SI = (1-p)·M, поправка по близнецам
                            ▲
data/external (ChEMBL) ─────┘  (пул соседей / доп. обучающие строки; строгая политика целостности)
```

* **Предобработка** (`chem/standardize.py`): родительская молекула (без солей), нейтрализация, канонический SMILES, InChIKey. Сырые строки сохраняются.
* **Признаки** (`features/`), блоки собираются в группы-уровни через конфиг (`features.groups`, `default_source_col`):
  счётчики фингерпринтов (Morgan 1/2/3, AtomPair, TopologicalTorsion, RDKit-paths, Avalon, MACCS, ErG, MQN), 203 RDKit-дескриптора,
  *условия ассея* (клеточная линия, токены вируса), *происхождение данных* (`meta`, `style`), **признаки-соседи**: взвешенные по сходству
  Танимото метки ближайших обучающих молекул, в целом и внутри «того же источника» (leave-one-out, поэтому согласованы на train и test).
* **Модели** (`models/`, реестр): ExtraTrees на разных представлениях молекулы (сильнейшее семейство), CatBoost, HistGB / LightGBM /
  XGBoost, ядерные модели (KRR, SVM) на ядрах Танимото. Для каждой — две задачи: `clf` и `reg`.
* **Валидация** (`cv/`): повторный стратифицированный 5-fold × 6; для каждой модели сохраняются OOF-предсказания, предсказания
  фолд-моделей на тесте и 6 переобучений на 100% обучающих строк (у CatBoost и ядерных моделей Brier на 8–9% лучше при 95% данных против 80%).
* **Ансамбль** (`ensemble/`): для `clf` — неотрицательный стекинг в logit-пространстве с L2-регуляризацией, минимизирующий Brier, для
  `reg` — среднее лучших моделей; выбор top-k происходит *внутри* фолдов (поэтому оценка не подглядывает). Изотоническая
  калибровка и обрезка вероятностей проверены вложенной CV и не приняты (не дают выигрыша).

Лучшие одиночные модели верхнего уровня — `reports/cv_leaderboard_final.txt`; отчёт ансамбля — `reports/ensemble_final.json`.

### Абляции (все — с тем же CV)

| что убрали | эффект |
|---|---|
| расширенные признаки стиля SMILES (v2: Кекуле-запись, доли символов, глубина скобок …) | Brier лучше: ExtraTrees на 2–9%, CatBoost на 16% (0.030 → 0.025) |
| все признаки происхождения (`@style`), ансамбль одного состава | 6.17 M → 8.38 M OOF-MSE |
| внешние строки как обучающие (CatBoost) | Brier −11%, RMSE log10 −2.9% |
| внешний пул соседей (модели с `knn`) | CatBoost/XGB чуть лучше, ExtraTrees ≈ 0 |
| вспомогательный пул чужих молекул (CC50 / EC50 / потенция скрининга, 3 914 молекул ChEMBL из репозитория коллеги; блок `aux_pool`) | **нет выигрыша**: Brier 0.0222 → 0.0223 (ExtraTrees), 0.0254 → 0.0249 (CatBoost), RMSE log10 0.712 → 0.722; пул далёк от наших серий (медиана максимума Танимото 0.49) |
| подсмотр значений тестовых молекул в ChEMBL (диагностика на train, запрещено организаторами, конфиги удалены) | на train итоговый MSE не менялся (6.55 M против 6.48 M, первый релиз данных): крупнейшие выбросы train — «ручные» записи, которых в ChEMBL нет |
| групповая поправка на тяжёлые серии, изотоническая калибровка, обрезка `p`, прямые модели сырого SI | не приняты вложенной CV (хуже или не лучше) |

## Внешние данные (требование организаторов)

Подробности и все колонки — `data/external/README.md`; лицензия — `data/external/LICENSE.md` (ChEMBL: CC BY-SA 3.0).

* **Источник:** ChEMBL REST API (`https://www.ebi.ac.uk/chembl/api/data`), эндпоинты перечислены в `src/vacv_si/external/chembl.py`.
  Идентификаторы `sid…` в `Title` — вещества PubChem из ассеев, зеркалируемых из ChEMBL, поэтому ChEMBL — первичный источник и для них.
* **Результат:** `data/external/vacv_external.csv` — 2 452 записи, 2 010 молекул, 168 статей, DOI у 100%, плюс колонки трассируемости
  (`ic50_activity_ids`, `cc50_activity_ids`, `cc50_assay_id`, `cc50_cell_line`, `cc50_same_cell`) и флаги качества.
* **Честные оговорки (все цифры — в `data/external/validation_report.json`):**
  * у 564 строк (23% из тех, где есть CC50) CC50 взят из *другой клеточной линии* той же статьи — помечено `cc50_same_cell = False`
    (переключатель `external.require_same_cell`);
  * 667 строк (27%) основаны на правиле «запись об активности без числа → `SI = 10000`»; оно проверено на 14 train-молекулах
    (13 из 14, интервал Уилсона 69–99%) — переключатель `external.sentinel_from_missing_ic50: false` убирает эти строки;
  * 92 строки делят ключ с другой записью (стереоизомеры или повторные измерения), 8 строк с `SI > 10 000` (нМ-активности) — всё помечено флагами.
* **Покрытие:** набор содержит 50% молекул train и 54% молекул test.

### Политика целостности

Раз 54% тестовых молекул есть в ChEMBL, их записи можно было бы «подсмотреть». Организаторы сообщили, что **это запрещено**, и пайплайн
этого не делает (`external.drop_overlap_with_eval: true` во всех конфигах, тест `test_no_config_looks_up_evaluation_molecules`): записи,
молекулы которых совпадают с валидационными/тестовыми (по связности InChIKey), из обучения исключаются, а пара «та же молекула»
маскируется и в признаках-соседях. Остаются аналоги (другие соединения тех же серий) — это «расширение набора», которое организаторы
разрешили. Внешние данные других молекул дают в основной модели почти ничего (CatBoost: Brier 0.0308 → 0.0303, RMSE log10 без изменений);
модель, обученная только на 2 020 внешних записях, на новых молекулах train не лучше константы по RMSE (1.009 против 0.977).
Поправка по близнецам (см. выше) использует метки *обучающих строк* соревнования; внешние данные нужны ей только для констант
(пары стереоизомеров других молекул), записи молекул теста она не смотрит.

## Как менять решение

Всё управляется конфигом (`configs/base.yaml` + `configs/exp/*.yaml`, наследование `extends:`, переопределения `-o a.b.c=значение`);
результаты моделей кэшируются по хэшу спецификации, данных, уровня признаков и версии кода признаков.

* **Новый блок признаков:** функция `(store, params) -> (матрица, имена)` с декоратором `@register_block("тип")` в `features/store.py`,
  строка в `features.blocks` и (по желанию) в группу `features.groups`.
* **Эксперименты и их результаты:** `experiments/README.md` (таблица для презентации), разведочные скрипты — `experiments/analysis/`.
* **Вспомогательный пул других молекул** (CC50, EC50, потенция …): блок `aux_pool` даёт признаки-соседи по пулу; сама молекула из пула исключается по InChIKey.
* **Новая модель:** класс с `fit(idx, y, w, ref)` / `predict(idx)` (см. `models/base.py`), регистрация в `models/registry.py`, строка в конфиге.
* **Новый эксперимент / уровень признаков:** файл `configs/exp/<имя>.yaml` с `extends: final.yaml`; уровни `chem.yaml` и `assay.yaml` —
  пример (переопределяют `features.groups` и `default_source_col`).
* **Эмбеддинги предобученных химических моделей (опция, в финальную посылку не входят):** `scripts/export_smiles.py` выгружает уникальные
  SMILES, `scripts/colab_embeddings.py` считает эмбеддинги ChemBERTa-77M (MLM и MTR) и CheMeleon (на CPU это секунды, GPU не нужен);
  MoLFormer и большие модели запускаются только с `--trust-remote-code` (код модели скачивается и исполняется, поэтому — на Colab:
  `notebooks/colab_embeddings.ipynb`), в этой версии они не запускались. Блок `npz_embedding` подключает эмбеддинги по стандартизованному
  SMILES, `scripts/make_embedding_configs.py` пишет `configs/exp/emb_{final,assay,chem}.yaml`: считаются только модели с эмбеддингами,
  а ансамбль подмешивает сохранённые модели уровня (`ensemble.include_tags`). Модели без файла эмбеддинга пропускаются, так что основной
  пайплайн от torch не зависит. Прирост в честном ансамбле около 1% MSE, то есть в пределах шума (`experiments/README.md`, № 26).

```
configs/            base.yaml, exp/{final,assay,chem,emb_*,ablate_*,ext*,...}.yaml
data/raw/           файлы соревнования (не в git)      data/external/   vacv_external.csv + README + LICENSE + validation_report.json
src/vacv_si/        data/ chem/ features/ models/ cv/ ensemble/ external/ cli.py
tests/              инварианты решения (синтетика)      reports/         отчёты ансамблей, OOF
scripts/            export_smiles.py, colab_embeddings.py, make_embedding_configs.py, summarize_results.py
notebooks/          colab_embeddings.ipynb                       submissions/   submission*.csv
```

## Ограничения

* 320 обучающих строк и тяжёлый хвост таргета: MSE на любой выборке теста сильно зависит от единичных выбросов (см. выше).
* Верхний уровень использует артефакты сборки датасета (происхождение данных). По правилам это допустимо (только входные колонки,
  без запрещённых), но это не «химия»: честная оценка «структура → SI» — нижние уровни.
* Один внешний источник (ChEMBL); отдельный сборщик PubChem не реализован: релевантные ассеи PubChem — зеркала ChEMBL, а qHTS-скрининги
  NCGC не содержат парных CC50/IC50.
* Гиперпараметры подобраны небольшим свипом, а не полным байесовским поиском.
* Лицензия на код не выбрана (данные — CC BY-SA 3.0, см. `data/external/LICENSE.md`).
